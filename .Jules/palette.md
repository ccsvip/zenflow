## 2024-06-15 - [Add explicit loading state to forms]
**Learning:** During async form submissions (like login), failing to explicitly disable interactive inputs (inputs, selects) alongside the primary submit button can lead to duplicate submission attempts, user confusion, or lost edits. The standard `<Button>` component has a built-in `loading` prop that handles its own disabled state, but sibling inputs require manual `disabled` properties and visual indicators.
**Action:** When creating or modifying async forms, always introduce a dedicated loading state (e.g., `isSubmitting`), pass it to the submit button's `loading` prop, and explicitly pass `disabled={isSubmitting}` to all interactive form fields along with appropriate `disabled:opacity-60 disabled:cursor-not-allowed` Tailwind classes to provide a consistent, clear UX.
